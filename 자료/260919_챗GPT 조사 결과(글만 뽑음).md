특히 제가 권하는 방향은 **“회원가입 없이, 개인정보를 서버에 저장하지 않는 무료 도장 PNG 생성기”**입니다. 이 구조라면 개발도 단순해지고 개인정보 리스크도 상당히 낮출 수 있습니다.

## 1. 먼저 벤치마킹 결과

현재 실제 페이지를 확인할 수 있었던 3개 서비스를 기준으로 보면 각각 장점이 뚜렷합니다.

| 서비스            | 확인되는 핵심 기능                       | 우리가 가져올 요소                   |

| -------------- | -------------------------------- | ---------------------------- |

| 싸인오케이          | 그리기·싸인·도장, 이름 입력, 생성, 다운로드       | **싸인/도장 통합 구조**, 단순한 UI      |

| Stampng        | 이름 → 모양 → 글씨체 → PNG, 비회원, 투명 PNG | **가장 직접적인 벤치마킹 대상**, 4단계 UX  |

| 도뉴             | 전자서명/도장 생성, 전자계약 서비스 연계          | 향후 **전자서명·문서 서비스 확장성**       |

| YouTube Shorts | 현재 링크의 영상 내용을 직접 판독하지 못함         | 실제 영상 내용을 확인하지 못했으므로 판단에서 제외 |

싸인오케이는 실제로 `그리기 / 싸인 / 도장` 탭을 제공하고 이름 입력 후 제작·다운로드하는 구조입니다. ([싸인오케이][1])

Stampng는 현재 **회원가입 없이 이름 → 모양 → 글씨체 → PNG 저장**의 흐름을 제공하고 있으며, 원형·사각형·타원형 등의 모양과 여러 서체를 제공합니다. ([도장 이미지 만들기][2])

또한 Stampng는 512×512 투명 PNG, 클립보드 복사, 모바일 공유, HWP·Word·Excel·PDF 등의 문서 활용까지 고려하고 있습니다. ([도장 이미지 만들기][3])

도뉴 역시 무료 전자서명/도장 만들기를 제공하면서 장기적으로 전자계약·API·온프레미스까지 연결하는 구조입니다. ([도뉴][4])

# 3. 가장 중요한 법적 구분

## ① 일반 도장 이미지 ≠ 인감증명용 인감

「인감증명법」은 행정청에 신고되어 있는 인감을 증명하기 위한 제도입니다. 즉 웹사이트에서 이름을 입력해서 만든 PNG 파일이 **자동으로 주민센터 등에 등록된 인감이 되는 것은 아닙니다.** ([법제처][5])

따라서 서비스 화면에 다음 문구를 명확하게 넣는 것을 권합니다.

> **본 서비스에서 생성되는 도장 이미지는 이미지 파일이며, 행정기관에 신고·등록된 인감 또는 인감증명서를 의미하지 않습니다.**

이 문구는 아주 중요합니다.

# 4. 전자서명과도 구분해야 함

여기서 상당히 중요한 부분입니다.

「전자서명법」은 전자서명이 단순히 전자적 형태라는 이유만으로 서명·서명날인·기명날인으로서의 효력이 부인되지 않는다고 규정하고 있습니다. 또한 법령이나 당사자 약정 등에 따라 전자서명을 선택한 경우 해당 전자서명이 서명 등의 효력을 가질 수 있도록 규정합니다. ([법제처][6])

전자서명*(Electronic Signature, 전자서명)*은 단순한 이미지 파일을 의미하는 것이 아니라, 법적으로는 전자문서에 결합되어 **서명자의 신원 및 해당 문서에 서명했다는 사실을 나타내기 위한 정보**라는 개념입니다. ([법제처][7])

따라서 우리 서비스에서는 처음부터 이것을 분리하는 것이 좋습니다.

### MVP

**도장 이미지 생성**

↓

PNG 다운로드

↓

문서에 삽입

### 나중에

**전자서명**

↓

본인확인

↓

서명시점·문서무결성 기록

↓

전자계약

이렇게 가는 겁니다.

이렇게 하면 사업 확장도 훨씬 좋습니다.

# 5. 가장 큰 법적 리스크는 오히려 '도장 자체'가 아닙니다

진짜 조심해야 할 것은 **타인의 명의를 이용한 문서 위조·변조**입니다.

현재 형법 제231조는 행사할 목적으로 타인의 문서 또는 도화를 위조·변조하는 행위를 처벌하고 있고, 제234조는 위조된 문서 등의 행사도 처벌 대상으로 규정합니다. ([법제처][8])

따라서 우리 서비스가

> “홍길동이라는 이름을 입력하면 홍길동 도장을 만들어준다.”

고 해서 서비스 운영 자체가 불법이 되는 것은 아닙니다.

하지만 **사용자가 그 이미지를 이용해 타인의 문서를 위조하는 것까지 서비스가 적극적으로 돕는 형태**가 되어서는 안 됩니다.

### 그래서 이용약관에 최소한 다음을 넣는 것을 권합니다.

* 타인의 명의 또는 상호를 사칭하기 위한 사용 금지

* 타인의 서명·도장을 무단으로 복제하는 행위 금지

* 공문서 및 사문서 위조·변조 목적의 사용 금지

* 인감증명 또는 행정기관 제출을 위한 공식 인감으로 오인하게 하는 사용 금지

* 금융기관·공공기관 등의 공식 직인이나 상징물을 무단 복제하는 행위 금지

* 불법적인 계약·증명·확인서 작성 목적의 사용 금지

이 정도면 MVP 단계에서 상당히 합리적인 안전장치입니다.

# 6. 공공기관 직인은 특히 조심

예를 들어

> 대한민국

> 국방부

> 육군참모총장

> 세종특별자치시장

등의 **실제 기관 직인을 그대로 재현하도록 만드는 기능**은 넣지 않는 것을 권합니다.

일반 사용자 이름으로 만드는

> 홍길동

> 김철수

> 우석

같은 개인용 도장은 괜찮지만,

> “국방부 공식 직인 만들어줘”

같은 기능을 적극적으로 제공할 이유가 없습니다.

**검색·생성 단계에서 차단할 수도 있습니다.**

다만 이것은 “법적으로 모든 기관명 생성을 무조건 금지해야 한다”는 의미가 아니라, **사업자 입장에서 불필요한 위험을 스스로 줄이는 설계**입니다.

# 7. 개인정보 측면에서는 오히려 아주 좋은 방법이 있습니다

여기서 제가 가장 강하게 추천하는 부분입니다.

## 서버에 이름을 보내지 않는 구조

사용자가

> 이우석

이라고 입력하면,

### 기존 일반 서비스

사용자

↓

서버

↓

도장 생성

↓

PNG

↓

사용자

가 될 수 있습니다.

그런데 우리는

### 권장 구조

사용자

↓

**브라우저에서 직접 생성**

↓

PNG

↓

사용자

로 만드는 겁니다.

즉,

**이름 → 도장 생성 → PNG 변환을 전부 사용자 PC/스마트폰에서 처리**

합니다.

이렇게 하면 서비스 서버가 사용자의 이름이나 도장 이미지를 저장할 필요가 없어집니다.

개인정보 보호법은 개인정보를 수집하는 경우 법적 근거가 필요하고, 불필요해진 개인정보는 지체 없이 파기하도록 규정합니다. ([법제처][9])

따라서 애초에 서버에서 이름을 받지 않는 구조가 훨씬 깔끔합니다.

# 8. 이것은 경쟁 서비스보다 좋은 차별점이 될 수 있습니다

예를 들어 첫 화면에 아주 크게:

> ### 🔒 입력한 이름은 서버에 저장하지 않습니다.

>

> 모든 도장 제작은 사용자의 브라우저에서 처리됩니다.

라고 표시할 수 있습니다.

단, **실제로 그렇게 구현했을 때만** 이렇게 홍보해야 합니다.

Stampng도 현재 이름 원문을 통계·로그에 저장하지 않는다고 안내하고 있으며, FAQ에서는 이미지 생성을 위해 API로 일시 전송한다고 설명합니다. ([도장 이미지 만들기][2])

우리는 여기서 한 단계 더 나아가 **아예 서버 전송을 제거하는 방식**을 목표로 잡을 수 있습니다.

따라서 최소한

**개인정보처리방침**

**이용약관**

**저작권/콘텐츠 정책**

**서비스 이용 주의사항**

정도는 준비하는 것이 좋습니다.

# 10. 저작권 측면에서 경쟁 사이트를 어떻게 벤치마킹할 것인가?

이 부분은 매우 중요합니다.

**기능을 벤치마킹하는 것은 괜찮지만, 경쟁 사이트를 그대로 복제하면 안 됩니다.**

예를 들어 다음은 피해야 합니다.

> 동일한 화면 구성

> 동일한 문구

> 동일한 아이콘

> 동일한 이미지

> 동일한 CSS

> 동일한 코드

> 동일한 도장 샘플

> 동일한 사이트 구조와 그래픽

저작권법은 창작성이 있는 표현을 보호하고, 컴퓨터프로그램도 저작물의 예시에 포함하고 있습니다. ([법제처][10])

따라서 우리는

**“기능 분석 → 완전히 새로운 UI/UX로 재설계”**

해야 합니다.

이건 제가 개발하면서도 계속 체크할 수 있습니다.

# 11. 폰트 저작권은 반드시 체크

도장 서비스에서 의외로 중요한 것이 **폰트 라이선스**입니다.

예를 들어 인터넷에서

> 궁서체

> 붓글씨

> 전서체

> 캘리그래피

등을 아무 폰트나 가져와서 서버 또는 웹사이트에 넣으면 안 됩니다.

특히 상업적 웹서비스라면

**상업적 이용 가능 여부**

**웹폰트 사용 가능 여부**

**재배포 가능 여부**

**앱/웹 서비스 내 embedding 가능 여부**

를 각각 확인해야 합니다.

따라서 처음부터

> OFL (Open Font License, 오픈 폰트 라이선스)

등 이용조건이 명확한 폰트 중심으로 구성하는 것이 안전합니다.

폰트 라이선스 파일도 프로젝트의 `/licenses/fonts/` 등에 보관하도록 설계하면 좋습니다.

# 21. 나중에 AI를 붙이는 것이 좋습니다

AI는 2단계에서 사용합니다.

예를 들어:

> “내 이름에 어울리는 도장 추천”

사용자가

> 우석

이라고 입력하면

```text

① 전통형

② 현대형

③ 수제형

④ 전문직형

⑤ 법인용

```

같이 자동 추천하는 것입니다.

하지만 이것도 처음부터 AI가 이미지를 생성할 필요는 없습니다.

**AI는 스타일 추천만 하고 실제 이미지는 로컬 엔진이 생성**하게 하면 됩니다.

이 구조가 훨씬 저렴하고 안정적입니다.

# 22. 사업 관점에서는 무료로 끝내지 않는 것이 좋습니다

무료 도장 만들기는 **트래픽 유입용 Entry Service**로 보는 게 좋습니다.

예를 들면:

```text

무료 도장 만들기

↓

무료 서명 만들기

↓

PDF에 도장 넣기

↓

PDF 서명

↓

문서 작성

↓

전자계약

↓

기업용 서비스

```

즉,

**무료 도장 → 사용자 유입 → 문서 업무 SaaS**

로 발전시키는 겁니다.

이 구조라면 단순 도장 사이트보다 사업적인 가치가 훨씬 커집니다.

# 24. 법적 안전성을 위한 화면 문구

서비스 화면 하단에 다음과 같은 문구를 두는 것을 권합니다.

### 서비스 이용 안내

본 서비스는 사용자가 입력한 이름 또는 문구를 바탕으로 도장 이미지를 생성하여 이미지 파일(PNG) 형태로 제공하는 서비스입니다.

본 서비스에서 생성되는 도장 이미지는 행정기관에 신고·등록된 인감 또는 인감증명서를 의미하지 않으며, 특정 문서의 법적 효력이나 제출 가능 여부를 보증하지 않습니다.

생성된 도장 이미지는 본인 또는 적법한 권한을 가진 자의 문서 작성 및 날인 목적으로만 사용하시기 바랍니다.

타인의 명의 또는 서명·도장을 무단으로 사용하거나, 문서의 위조·변조, 허위 증명, 사칭 또는 기타 불법적인 목적으로 사용하는 행위를 금지합니다.

공공기관, 금융기관, 법인, 단체 등의 공식 직인이나 표장을 권한 없이 복제하거나 사칭하는 용도로 사용해서는 안 됩니다.

문서 제출 또는 계약 과정에서 전자서명이나 인감 날인이 요구되는 경우에는 해당 기관 또는 계약 상대방이 요구하는 방법과 요건을 별도로 확인하시기 바랍니다.

이 문구 자체는 최종 출시 전에 **국내 변호사 또는 법무 전문가의 검토를 한 번 받는 것**을 권합니다.

# 25. 최종적으로 제가 평가한다면

| 항목             | 판단                             |

| -------------- | ------------------------------ |

| 서비스 구현 가능성     | **매우 높음**                      |

| 개발 난이도         | **낮음~중간**                      |

| VS Code 개발     | **가능**                         |

| Claude Code 활용 | **매우 적합**                      |

| 서버 필요성         | **MVP에서는 최소화 가능**              |

| 개인정보 위험        | **브라우저 로컬 처리 시 낮출 수 있음**       |

| 도장 이미지 생성 자체   | **가능**                         |

| 법적 리스크         | **관리 가능**                      |

| 가장 주의할 부분      | **타인 명의·문서위조·공공기관 직인·전자서명 오인** |

| 저작권 리스크        | **경쟁 사이트 복제와 폰트 라이선스 주의**      |

| 사업 확장성         | **높음**                         |

### 제 판단

**만드는 것을 추천할 수 있는 아이템입니다.**

특히 단순히 `도장 PNG 생성기` 하나만 만드는 것보다는,

> **무료 도장 → 무료 서명 → 문서에 넣기 → PDF 편집 → 전자서명 → 전자계약**

으로 이어지는 **문서 업무 도구 플랫폼의 첫 번째 무료 유입 서비스**로 설계하는 것이 훨씬 좋습니다.

그리고 중요한 점은 **처음부터 AI SaaS로 만들 필요가 없다는 것**입니다. 도장 생성 자체는 브라우저에서 처리하고, AI는 나중에 “디자인 추천·문서 자동화”에 붙이는 편이 기술적으로도 경제적으로도 유리합니다.

현재 기준으로 Claude Code 자체는 터미널에서 프로젝트 파일을 직접 탐색·수정하고 테스트까지 수행할 수 있으므로, **VS Code + Git + Claude Code 조합으로 이 프로젝트를 실제 개발하는 것은 충분히 가능합니다.** ([Claude Platform Docs][11])

다음 단계에서는 바로 개발에 들어갈 수 있도록 **① 서비스명/메뉴 구조 → ② 실제 화면 와이어프레임 → ③ 기능명세서(PRD) → ④ Next.js 프로젝트 구조 → ⑤ Claude Code에 그대로 붙여넣는 개발 프롬프트 → ⑥ 이용약관·개인정보처리방침 초안**까지 한 번에 설계하는 것이 가장 효율적입니다.
